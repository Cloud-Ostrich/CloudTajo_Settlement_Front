# 운영 대시보드 조회 조사 (2026-10-09)

관리자 인증 후 summary, 목록, 상세 GET만 조회했다. 영수증 변경 API는 호출하지 않았다.

## 실제 응답

`GET /api/admin/dashboard/summary?month=2026-10`:

```json
{"month":"2026-10","totalAmount":0,"categorySummaries":[],"pendingCount":1,"rejectedCount":0,"averageReviewMinutes":0}
```

`approvedAmount`, `settledCount`는 응답에 없으며 다른 이름의 대체 필드도 없었다. 나머지 이름은 프론트와 일치한다. 금액 0과 빈 카테고리 배열은 서버 응답 자체이다.

비교 조회:

| 월 | totalAmount | 카테고리 금액/건수 | averageReviewMinutes |
| --- | --- | --- | --- |
| 2017-07 | 200000 | 식비 200000 / 2 | -250.225 |
| 2022-10 | 109000 | 식비 109000 / 1 | -500.3333333333333 |

상세에서 ID 1·3의 확정 금액은 각각 100000, 확정 결제일은 2017-07-05, 제출일은 2026-10-08이었다. ID 2의 확정 금액은 109000, 결제일은 2022-10-04, 제출일은 2026-10-08이었다. 모두 SETTLED 상태이다. 이는 결제 월에 해당 정산 건을 집계하는 동작과 부합한다. 다만 서버 코드나 공식 월 기준 계약을 확보하지 못했으므로 확정된 계약으로 단정할 수 없다.

ID 15·16은 SETTLED이나 확정 금액·결제일이 null이다. ID 17은 REVIEWING이며 확정 금액·결제일이 null, OCR 원본은 100000 / 2017-07-05였다. ID 19는 REVIEWING이며 확정 금액 2300, 결제일 2026-10-01이지만 10월 summary는 여전히 totalAmount 0이었다. 따라서 null 확정값만으로 10월 집계 결과 전체를 설명할 수 없으며, 집계 대상 상태·조회 조건도 확인해야 한다. 목록은 items/page/size/totalElements/totalPages 구조이다.

## 프론트 처리

- summary에서 받은 값만 표시하며 상세/OCR 원본으로 집계를 만들지 않는다.
- 0은 정상 수치로 표시한다. null은 `집계값 없음`, 누락 또는 부적절한 수치는 `집계 정보 없음`으로 표시한다.
- 카테고리 빈 배열은 해당 월 집계 없음, null·누락은 카테고리 정보 미제공 안내를 표시한다.
- 음수 평균 검토 시간은 기존대로 표시하지 않는다.
- 월 파라미터와 OCR·승인·목록 보완 흐름은 변경하지 않는다.

## 백엔드 확인 및 수정 필요

1. 승인 금액과 정산 완료 건수를 제공하려면 summary DTO와 쿼리에 approvedAmount/settledCount를 추가하고 계약을 문서화한다. 0과 미제공을 구분한다.
2. 월 기준(submittedAt 또는 paidAt), 상태별 집계 대상, totalAmount의 의미, 금액 null 처리, 카테고리 count 조건을 문서화한다. 현재 문서의 '제출 금액' 설명과 결제 월에 집계되는 관측 결과가 다르다.
3. ID 19의 확정 금액이 10월 totalAmount 및 카테고리에 포함되지 않는 이유를 확인한다. 의도된 상태 조건인지, 누락된 조인·필터인지 서버에서 확인해야 한다.
4. ID 15·16처럼 과거 정산 건의 확정값이 null이면 SUM에서 금액이 제외되거나 paidAt 월 필터에서 건 전체가 제외될 수 있다. 실제 쿼리를 확인하고 미확정 정산 건을 별도 진단한다. 과거 값 보정에는 관리자 확인이 필요하며 OCR 원본을 자동 확정하지 않는다.
5. 평균 검토 시간이 음수인 원인을 확인한다. 제출·결정 시각의 차감 방향, 선택 이력, 타임존, 잘못된 이력을 검증한다. 표본이 없는 경우 0인지 null인지도 계약으로 정한다.
6. 카테고리 빈 배열이 상태 조건 때문인지 결제일/null 제외 때문인지 쿼리로 확인한다. 클라이언트는 빈 응답의 내부 원인을 판별할 수 없다.

공개 API 문서 경로에서는 유효한 OpenAPI 계약을 확보하지 못했다. 위 원인 추정은 응답 관측에 기반하며 서버 구현 검증을 대신하지 않는다.
